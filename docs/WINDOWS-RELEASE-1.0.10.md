Windows 1.0.10：适配官方客户端 26.1103.4239.0，并补齐更新与重启后的恢复机制。

本次确认的原因：

- 旧主题记录指向已被 Windows 分配给 svchost.exe 的进程号。旧代码读取受保护进程的创建时间失败，启动因此中断。
- 官方应用改为 early-bootstrap 与多个模块；旧探测器只寻找 main 文件，且不识别新版压缩器反转后的严格相等表达式。原有窗口恢复接口仍存在。

修复行为：先用系统启动时间确认旧注入器是否属于上一次启动；同次启动时，原生时间不可读则尝试 CIM 创建时间，处理精度差异。只归档确认失效的元数据，不结束进程号的当前占用者。保留原端口提示，身份信息不足时仍不猜测。

窗口能力检查改为有数量与字节上限的构建模块扫描，识别相同接口的不同文件名、模块拆分和比较顺序；仅唯一匹配已审查的恢复/显示/聚焦分支才执行。保留签名包身份、回环端口、Browser ID、主页面与原生窗口校验。官方应用文件不修改。

新增回归覆盖：受保护进程、跨重启记录、同次启动 PID 复用、CIM 时间精度、模块拆分和反转比较。不开机自启的设置保持不变。

自动适配范围是仍满足已审查接口语义的客户端更新；重大接口或页面结构变化仍可能需要后续修复。不下载执行远程补丁，不保证任意未来版本无需维护。Mac 保持 beta.5，Android 原型不受本次 Windows 修复影响。

升级前的安装文件、日志和源码已在本机备份。素材与上游引用见 THIRD_PARTY_NOTICES.md。

本机验证：完整主题校验通过；桌面入口约 7.08 秒，任务栏快捷入口约 7.47 秒，真实隐藏窗口唤回约 7.33 秒；理世图标、等待时 Esc 与提前关闭动画后继续启动通过，原会话保留。此处为已有会话与失效状态恢复测试，不代表整机重启后的完整冷启动测速。新增 Windows CI 自动运行状态恢复和窗口能力回归，CI 使用夹具，不包含真实 Store 客户端更新测试。
