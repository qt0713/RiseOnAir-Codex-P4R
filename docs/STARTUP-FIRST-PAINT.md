# 启动检查与回退

Windows 1.0.7 与 macOS 1.1.0-beta.4 将启动检查分为两步。它们仍使用上游注入事务、签名/注册包验证、受管目录及已验证的调试连接，不改动官方应用。

1. 启动阶段：播放展示动画，同时启动/恢复客户端和主题注入。确认正确主题 ID、payload revision、引擎版本、样式实际存在、壁纸解码完成且在可见页面元素或伪元素上使用、基础页面结构就绪。Windows 再校验真实主窗口 HWND 和 Browser ID。只有这一步通过才交接。
2. 后台审计：另起只读进程执行上游完整布局检查。结果记录在 Windows `logs/background-audit.*` 或 Mac `~/Library/Application Support/RiseOnAir/background-audit.log`。不因审计延迟挡住启动，也不因审计失败卸载已显示的主题。手动验证不启用首帧模式。

Chromium 会把被其他窗口完全遮挡的 Windows 页面标记为 hidden，因此该平台依靠经过身份匹配的原生窗口检查区分遮挡和真正隐藏。未匹配到可见主窗口时不能报告就绪；Mac 首帧检查仍要求 renderer 可见。

Windows 正常启动避免重复种入所有主题预设，仍保留事务恢复和活动主题内容校验；应用首次安装/升级负责主题准备。Mac 已有会话探测采用 1.5 秒预算，未通过才启动恢复流程；保留登录项位置更新，确保移动应用后下次登录仍能找到启动器。

参考项目：[dragon-codex-boot，c63a203](https://github.com/yushua0808-cpu/dragon-codex-boot/tree/c63a203e5857e85fb3c8a9891eddb570e7a27b54)。本次采用其并行启动与窗口交接思路，未复制视频、图像、声音或源码。该项目不承担主题注入，不能证明本项目的真实主题加载速度。

## 备份与回退

修改前在维护机器上保留了源码归档、Git 提交号、Windows 1.0.6 安装包、Mac beta.3 两种安装包、现有安装文件及活动主题/引擎，未复制登录资料或浏览器资料。备份有 SHA-256 清单和 Windows 回退脚本，私人备份不上传 GitHub。

Windows 适配器使用固定上游 SHA-256、原始文件备份和精确文本锚点，拒绝覆盖未知修改。卸载/移除适配器可还原两个原始引擎脚本。退回旧包前需先移除新版适配器，否则旧包会因未知修改而拒绝覆盖。不能仅以“覆盖 EXE”作为引擎回退。

Mac 可保留旧 DMG/ZIP，保存输入并退出官方客户端后替换 Rise On Air.app，再运行完成受管引擎部署。备份包须与对应 Release 的 SHA256SUMS 一致。

## 测试边界

单元与故障测试覆盖旧主题/旧 revision、样式缺失、壁纸未就绪、伪元素 Blob 壁纸、隐藏窗口、空页面、布局基础结构缺失，以及慢速/失败后台审计不阻塞 Mac 启动。Windows 本机测试保留已有客户端，不等于重启电脑后的完全冷启动。GitHub Mac CI 检查两种 CPU 的原生构建、WKWebView 播放、资源安全和安装包，不包含真实用户登录会话。实际耗时需结合本机阶段日志复核，不能用动画的 3.2 秒充当加载耗时。
