Windows 1.0.9：修复更新或重启后的旧进程记录，并取消窗口恢复的固定客户端版本名单。

这次实际失败的直接原因是旧主题注入器的进程号被 Windows 分配给了另一个系统进程。上游拒绝处理身份不匹配的进程，导致主题启动中断。本版在操作锁内核对进程创建时间：只有确认旧进程已不再存在时才归档其状态记录，保留当前占用者、Codex 会话、主题和原浏览器端口。无法读取或判断身份时仍保留记录，不猜测、不结束进程。

后续 Codex 更新后的自动适配：

- 每次启动继续动态发现当前注册的官方包。
- 隐藏窗口恢复改为只读检查该包中真实的窗口处理分支。允许已审查的恢复、显示、聚焦逻辑以及变量名、打包文件名、引号变化，不再按固定版本号放行；不执行读取到的官方代码。
- 保留回环端口、进程归属、Browser ID、唯一主页面和原生窗口校验。接口结构改变时拒绝未知私有调用。
- 主题失败时优先显示已有官方窗口，否则请求官方包启动；收起动画并记录主题未验证，不伪装主题成功。等待超过 20 秒时收起等待画面，已经请求的后台启动继续，Esc 仍可提前跳过。
- 不开启开机自启，不自动下载或执行远端适配代码，不修改 WindowsApps / app.asar。

验证于官方客户端 **26.1021.3705.0**：旧状态恢复并重建主题约 13.47 秒；已有会话桌面入口约 6.04 秒、任务栏快捷入口约 6.34 秒、隐藏窗口恢复约 7.05 秒。完整主题检查与截图通过，理世窗口图标通过，现有会话保留。独立副本强制主题失败后约 4.60 秒退出动画并唤回官方窗口，未写入主题成功标记。旧系统进程仍然存活，登录启动项与启用标记均不存在。

回归测试覆盖进程号复用、同代进程保留、异常创建时间、非默认端口保留、未来打包命名与引号变化、未知窗口协议拒绝和异常 ASAR 边界。上述实测不是整机重启后的完全冷启动测试。

**自动适配有边界**：窗口协议、页面结构、调试机制发生实质变化时仍可能需要更新本项目。本版实现自动检测、已知接口复用和可继续使用官方客户端的降级，不保证所有未来版本都能自动恢复完整主题。Mac 保持 beta.4；本次修改针对 Windows 进程与窗口机制。
